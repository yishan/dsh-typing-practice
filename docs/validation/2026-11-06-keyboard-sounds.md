# 键盘音效：来源与验证

日期：2026-11-06。

## 同类实现与素材选择

| 项目 | 已核对的参考点 | 本轮采用方式 |
| --- | --- | --- |
| [Monkeytype 设置](https://monkeytype.com/settings?highlight=minWpm) | 声音选择与音量独立，提供 NK Creams、Cherry MX Black／Blue／Brown 等声音，不同键帽配置可分开列出 | 参考紧凑的音色选择、音量和默认静音交互；未复制其录音 |
| [Mechvibes sound packs](https://mechvibes.com/docs/sound-packs) | 用声音包组织素材，支持制作与分享；不同声音包可以使用不同许可 | 参考按声音包组织普通键与特殊键；未将应用代码许可当作社区声音包的统一许可 |
| [kbsim](https://github.com/tplai/kbsim) | 键盘声音模拟器与打字练习，仓库包含多种轴体录音，使用 MIT 许可 | 采用四套按下录音；保留固定版本、原始文件、校验值和作者许可 |

源版本为 `ba103f3b0afa9dab80447aa2e7e2ed80b6bd80e4`。作者 Thomas Lai，原始许可见 [上游 LICENSE.md](https://github.com/tplai/kbsim/blob/ba103f3b0afa9dab80447aa2e7e2ed80b6bd80e4/LICENSE.md)。首批选择 Cherry MX Blue、Cherry MX Brown、NovelKeys Cream、Holy Panda，兼顾几种不同按键声音，并将素材总量控制为 29 个 MP3、67,240 字节。各录音保持原样，构建前检查 SHA-256。

声音包来自具体键盘配置，轴体名称不能单独决定键盘的实际声音。本轮没有加入用户导入、系统全局键盘监听、错误提示音或抬键声。

## 已实现行为

- 「音效」入口位于「记录」旁，打开独立原生 dialog。沿用当前主题、按钮、下拉箭头和焦点样式；状态区域预留高度，准备与错误提示不推动控件。
- 默认关闭，音量默认 30%。音色、音量立即保存至独立的 `dsh.typing-practice.sound.v1`；清空记录保留声音选项。设置窗口支持 Tab、原生下拉选择、滑块键盘调整及 Esc 关闭，关闭后焦点返回入口。
- 用户交互后创建／恢复 AudioContext，按需加载 `client.audio.js`。普通按键不排队补播；录音只解码一次并缓存。每次按键最多触发一个声音，最多八个声音重叠。
- 仅聚焦练习输入区且本轮可接收输入时播放。导航键、快捷键、长按自动重复及截止后的输入不播放。IME 组字按可观察 keydown 播放，批量上屏事件不增加播放次数。
- 失焦、页面隐藏、重开、结束、切换声音或静音会停止当前及预约声音。关闭试听窗口取消迟到的试听；组件卸载释放节点与 AudioContext。
- 音频缺失、解码失败、resume 失败或保存失败不会阻断输入与判分；音效窗口保留重试入口。

## 自动检查

Node 测试共 104 项通过，其中新增 11 项音频引擎与组件测试。覆盖：

- 声音包切换、五种普通键变体、特殊键映射、青轴回退、解码缓存与录音校验。
- 首次加载不补播，异步切换只采用最后选项，最多八个声音重叠，音量为零时停止。
- 默认关闭、刷新偏好读取、存储损坏、保存失败，以及清空记录不改变音效选项。
- IME 的多个按键与批量上屏分开计数；快捷键、重复、未聚焦及截止后输入不响。
- 关闭／隐藏／卸载取消试听，分块加载、解码、resume 和播放失败可恢复，练习仍能结束。

单元测试使用模拟 AudioContext。真实解码和信号另由下述浏览器检查确认。构建、JavaScript 语法与发布清单检查不代替真实设备听音。

`npm pack --dry-run` 的预构建通过；发布清单包含 `client.audio.js`（92,502 字节）与完整 `THIRD_PARTY_NOTICES.md`，总计 15 个文件。`node --check` 和 `git diff --check` 通过。打包使用临时 npm 缓存，以避开全局缓存目录的写入限制，未改变全局 npm 配置。

## 浏览器检查

使用独立端口的模拟 DSH 宿主页，加载实际 `client.js`、音频分块、React 18 和 DSH 主题。人工构造的语料及测试 localStorage 与用户数据隔离。宿主页记录 AudioContext 的解码／播放次数，并用 AnalyserNode 检查输出信号；这些观测代码不进入插件。

| 场景 | 观测结果 |
| --- | --- |
| 首次打开／关闭状态 | 没有创建 AudioContext；试听按钮禁用 |
| 四套音色依次试听 | 29 个文件全部成功解码；每次试听预约四个声音；四套音色均出现非零信号 |
| 连续五次真实 DOM 按键 | 播放计数恰好增加 5，输入与计时继续 |
| 宿主输入框填写 | 未增加插件音效播放次数；单元测试另覆盖未聚焦 keydown |
| 音量与刷新 | 音量从 30% 调为 35%；刷新后恢复 Holy Panda 与 35%，尚未交互时仍未创建 AudioContext |
| 设置关闭 | Esc 关闭并返回音效入口；试听停止 |
| 进行中的练习 | 音效与记录入口禁用，重开后恢复 |
| 360px 中英界面 | 页面无横向溢出，窗口宽 328px；内容、箭头、滑块和试听按钮均可见 |
| 桌面界面 | 窗口随内容收紧，宽 440px；未改变练习页整体样式 |
| 控制台 | 检查时没有 warn／error |

## 验证边界

本轮验证了浏览器真实音频解码和非零输出信号，未通过人耳确认系统扬声器／耳机的最终声音、响度或设备延迟。原生 DSH 本轮位于另一聊天页面，未切换并验收原生宿主的声音分块加载。真实中文／粤语输入法可能吞掉部分 keydown，音效只跟随浏览器能观察到的事件；本轮 IME 音效隔离由组件测试覆盖，尚未完成实际输入法的听音验收。此前输入层的真实 IME 验证不替代本轮音效验证。
